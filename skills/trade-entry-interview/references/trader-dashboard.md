# Trader Dashboard 记录约定

先检查当前项目的 `journal.py`、`server.py` 和前端，不假定旧接口仍然有效。使用现有 UI 或已授权的应用保存入口；本文件不包含域名、服务器、账号或凭证。

- 创建前按交易所、合约、实际开仓时间/成交标识查重。核对自动归档的已有记录，优先追加用户笔记。
- 当前笔记保存入口为 `POST /api/journals` / `journal.save_journal`。更新时保留记录 ID，用已有字段值作 `base_values` 冲突检查，不覆盖同时发生的修改。
- `thesis` 保存原始开仓理由。`invalidation`、`exit_plan` 分别存用户确认的失效/退出条件；尚未回答留空。访谈进行中的内容不是平仓后的 `reflection`，不应完成复盘打卡。
- `entry_price`、`quantity`、`opened_at` 只填已核实事实。`timeframe` 记录用户的决策周期；附图周期另记。例如用户说 5m 而附图为 3m，两者同时保留。
- 若用户没说明交易所，先从当前已授权的持仓/成交页面核对；不能因图表标题写 Binance 就把 Variational 的交易归到 Binance。
- 现有 `images` / `screenshot_snapshot` 可存历史截图证据，但普通笔记保存接口可能不接受这些扩展字段。先检查当前实现；没有可用入口时保存私有附件及关联说明，不静默丢弃，也不绕过应用校验直接覆盖整份数据库。
- 成交后补记明确注明补记时间。持仓页和订单页可能是不同抓取时点；源时间分别保留。截图价格、订单触发价、实际成交价不混用。
- 费用、资金费或平仓结果未核实则保留未知，不能记成零。手工/浏览器快照不冒充 API 自动同步，不进入已核对合并收益。
- 最后回读保存的记录和附件可见状态；失败则明确报未保存并保留私有草稿。用户补充下一轮回答后更新同一记录。
