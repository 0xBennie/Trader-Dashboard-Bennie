# 开仓理由访谈

目的：用尽量少的输入留下可复盘的原始判断。一次只问一个关键问题；能从已授权账户或已提供材料核对的成交事实，不再要求用户重填。

## 开始

- 先区分准备开仓、已经成交、平仓复盘。已经成交的回答是事后补记，保留实际填写时间，不能伪装成开仓前计划或事前 AI 审核。
- 核对交易所、合约、方向与成交时间，查找已有日志后追加，避免一笔交易重复创建。截图的行情来源未必是执行交易所，当前报价也不是成交价。无法确认的字段留空。
- 用户已经给出的理由，原样保留，不重复提问。尚未给出时，第一问：
  **“回到下单那一刻，你为什么选择现在开这笔？最打动你的那个信号是什么？用当时的原话说就行。”**
- 本次任务可以记录截图和回答时，先保存已知信息，不等待所有字段齐全。只在写入并回读成功后说“已记录”。

## 按缺口追问

每收到一轮回答，先简短复述并保存，再从下列缺口中选择最重要的一项。不是每笔都问完整套题。

- **依据具体是什么**：若只说“支撑”“突破”“感觉要涨”，问哪个周期、哪个价位或区间，以及当时实际观察到了什么。不要替用户补出“放量确认”等没有说过的理由。
- **什么情况证明错了**：询问可观察的失效条件。若止损挂单已核实，直接引用价格，只追问它对应什么结构、是否还有提前退出条件，不让用户重报价格。
- **为什么此刻执行**：当“到位置”与“确认信号”仍混在一起时，问当时是直接试单还是看到具体确认后入场。不要预设哪一种更正确。
- **怎样结束这笔交易**：已有止盈挂单则先记下；必要时问预期持有多久、迟迟不按预期走怎么办。利润保护规则沿用用户当前设置，不默认设置固定百分比。
- **执行与心态**：只有用户提到追价、报复、临时加仓等或主动要求时再追问，不强迫每笔填写情绪问卷。

支持“没想清楚”“直觉”“先跳过”：保存为未量化判断或待补充，停止追问该项。不能把它改写成完整策略、杜撰信心分数或盈利概率。

## 保存与反馈

把以下三类内容分开：
1. **原始理由**：用户原话、回答时间、对应问题；后来修改追加版本。
2. **已核实事实**：实际成交/仓位/订单、来源与抓取时间。浏览器快照属于当时页面证据，不等同持续 API 同步或已对账盈亏。
3. **待确认事项和分析**：未提供的支撑区、失效条件等明确列出；AI 整理标为整理，不写进原话。

结束时用几行给出已记录事实、当前理由和一个最有价值的待补问题。已有挂单不等于用户解释了逻辑；计划完整度不等于收益保证。访谈可分多次继续，不因用户离开而丢弃已保存部分。

## 连接交易手记

在 Trader Dashboard 项目工作时读取 [账本接入约定](references/trader-dashboard.md)。在其他项目使用其现有保存入口，不套用本项目地址或数据结构。此 Skill 负责对话与记录；安装它不会让网站、浏览器或定时任务自动常驻运行。

交易所页面只读取已授权范围内的仓位、成交和挂单。记录授权不包含创建、修改或取消交易订单；也不包含公开分享私人交易。
