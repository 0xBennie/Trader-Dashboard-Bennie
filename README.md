# Trader-Dashboard(Bennie)

**交易手记 · 自托管的交易记录与复盘工作台**

个人交易记录与复盘工作台。使用 Python、SQLite 和原生 JavaScript，自托管运行；支持 Binance USDⓈ-M、OKX / Bybit USDT 永续只读采集、外部交易所截图归档、可选 AI 服务商分析和事前计划审核。

## 当前能力

- 后台采集成交、持仓、挂单、账单和行情快照；网页关闭不影响服务端采集。
- 总览分别展示 Binance、OKX、Bybit 数据状态与外部截图记录待核对状态，按真实挂单核对固定止损覆盖。
- 交易日志按交易所、状态筛选；个人笔记分段，草稿和历史版本保留。
- 复盘页直接回看近 30 天已确认平仓的成交结果、费用范围和个人笔记；个人笔记与 AI 报告分别保留。
- 每天香港时间 21:00 保存事实日报；无 AI Key 也会整理平仓、新归档、待核对与待复盘记录。
- AI 任务持久排队，独立于交易所连接运行；缺 Key 等待、失败有限重试，连接后继续。
- 收益按真实账单的平仓盈亏、手续费及资金费计算；不包含划转，不冒充账户权益。
- 四个主入口：总览、交易、复盘、分享。手机采用固定底部导航；顶部「更多」提供 AI 配置和导出。连接设置按交易所与 AI 服务分区，支持键盘切换。
- 月度、年度和单笔交易分享卡片，贡献日历、PNG 导出，以及可撤销的固定报告链接。
- 账号密码登录、服务端密钥保存；页面与账户数据不进行离线缓存。

本应用不创建、修改或取消交易订单。风险政策由使用者确认后启用，历史交易不追溯判为违规。Variational 目前只支持独立记录，尚未自动同步个人仓位或盈亏。

## 本机运行

需要 Linux 或 macOS、Python 3.10+。运行 Node.js 测试时需要 Node.js 20+。服务使用 Unix 文件锁；Windows 可在 WSL 中运行。

```sh
git clone https://github.com/0xBennie/Trader-Dashboard-Bennie.git
cd Trader-Dashboard-Bennie
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 server.py
```

打开 `http://127.0.0.1:8765`。全新实例默认仅监听本机，账本为空。可以先新建手动日志；需要自动同步时，再在连接设置中填写对应交易所的只读凭证。AI 是可选项，不配置也可以记录和复盘交易。生产实例不能使用无认证的本机启动方式直接暴露公网。

凭证、账本和附件属于部署实例，不属于开源源码：

- `.env.local`：Binance 凭证，也可从页面配置。
- `data/journal.sqlite3`：交易、账单、日志、历史和报告。
- `data/exchange-accounts.json`：OKX / Bybit 凭证与账户绑定（权限 0600），不会包含在导出或公开源码中。
- `data/ai-config.json`：各 AI 服务商的独立配置和密钥（仅服务端存储，权限 0600）。
- `data/auth.json`：登录配置与密码哈希。
- `static/assets/`：私人附件；源码只发布 favicon 和两个通用应用图标。
- `research/`：本实例生成的研究数据及结果。

同一账本只运行一个服务进程。生产数据是唯一主账本；开发和浏览器验收使用独立数据库，关闭采集和自动 AI，不能用开发副本覆盖线上数据。

## 第一次使用

1. 打开「交易 → 补充笔记」，填写自己的交易信息和入场判断。网页新建默认是 Binance 日志。
2. 如需自动采集，在「连接设置 → 交易所」选择 Binance、OKX 或 Bybit，填写对应凭证。使用只读权限，避免为本应用授予交易或提现权限。
3. 如需 AI，在「连接设置 → AI 服务」选择服务商、模型并填写自己的 Key。模型调用由所选服务商按其规则计费。
4. 在「复盘 → 交易回顾」直接浏览已结束交易的结果和证据，按需留一句判断或查看 AI 报告。首页只提示采集与数据问题，不把未写笔记当成待办。

Variational 支持独立截图记录与经授权浏览器观察导入。`browser_journal.py` 使用稳定成交标识去重，保留原始理由，核对全仓平仓后进入复盘列表。它不连接交易所 API，也不自行操控浏览器；定时浏览器采集需要部署者另行配置 Codex 任务，并保持电脑、浏览器扩展及登录可用。登录失效时保留旧数据并显示状态。已有外部记录也可通过登录后的 `POST /api/journals` 接口创建；请求需要合法会话及 `X-Journal-Token`。截图与浏览器记录不进入已对账 API 合并收益。字段与操作约定见 [自动复盘工作流](skills/trade-entry-interview/references/automatic-review.md)。

日报覆盖前一日 21:00 至当日 21:00，按已核实平仓时间归属，保留生成时证据。服务恢复后补存最近到期的一份，不回造离线持仓快照。日报可从「复盘 → 自动复盘 → 历史日报」查看；站外每日推送由部署者配置的 Codex 定时任务负责，源码不会默认向第三方发送私人数据。

仓库中的 [合成示例](examples/synthetic-journal.json) 仅用于说明字段，不会自动导入或冒充真实成交。

## 让复盘变成下一次行动

「交易 → 开仓前问助手」提供公开行情、个人记忆与计划风险检查。填写理由、决策周期、入场价，按需补充数量、止盈止损、账户权益和预算；系统核算毛风险及盈亏比，给出待确认的结构价位候选。用户确认的金额风险上限保存在私人记忆中，临时填写更高预算不会覆盖该上限。预算按 USD / USDT 区分，不隐式换算。AI 分析为可选调用，缺 Key 时仍可使用行情与规则检查。此咨询不产生交易许可，不取代原有 Binance 纪律审核。

页面顶部的「下单前 10 秒」卡片只需入场价和止损价，按已确认的单笔风险上限向下取整算出数量、名义价值和盈亏比，可一键带入完整检查。已确认平仓的净亏损（Binance / OKX / Bybit 成交或经核对的 Variational 浏览器平仓），或你手动点「我刚止损了」，会开启默认 30 分钟的冷静期提醒，首页和开仓前检查都会显示；它只是提醒，不阻止下单，未同步的外部仓位不会被自动识别。

每笔日志新增「K 线与交易回放」，按入场附近和必要的离场窗口保存已收盘永续 K 线，支持切换周期及“只看当时已知走势”。实际入场时间未知时围绕归档时点展示并标注，不推断入场精度。Binance、OKX、Bybit 分别读取本交易所公开 USDT 永续行情；Variational 使用明确标注的 Binance 参考行情，不作为 Variational 成交或止损触发证据。行情窗口有界保存，不把未覆盖的中间走势当作完整持仓过程。可取得时补充观察时点之前的历史 OI、已结算资金费率和同窗口相对 BTC 涨跌幅；新闻和私人指标公式未接入。

个人记忆分为本人确认和待验证假设，可修改、归档，并保留历史。原始开仓理由和个人复盘按日志关联，AI 不自动改写。`data/trader-memory.md` 是从私有数据库生成的可下载文档，不提交到 Git；在页面修改，直接编辑导出文件会在下次生成时被覆盖。每次 AI 复盘与开仓咨询都带上有来源的相关记忆和 K 线快照；缺失行情会明确记录。后台为近 30 天日志逐笔补存公开行情，与可独立暂停的浏览器采集无关。

日常默认只显示一段个人笔记，按需填写。想做细致复盘时，在「交易 → 我的交易笔记 → 持仓观察与复盘 → 深入复盘（可选）」记录执行评价、改进问题、做对的地方，以及「下一笔只改一件事」。保存后可主动将这句话加入首页提醒。

「复盘 → 问题标签与改进记录」是默认收起的可选工具，按近 30 / 90 天及交易所汇总本人标记的问题，并链接回原交易。提醒不受统计时间范围限制；新交易入场并平仓后，可以关联一次实践，填写「做到了 / 还没做到」及实际过程。实践可撤销更正，提醒可收起恢复，历史保留并随完整账本导出。问题标签与执行评价是本人判断，不由盈亏推断，也不替代交易所成交证据。

## 数据与复盘口径

自动采样不是逐笔行情。服务停机、网络断开或设备休眠期间的持仓和挂单过程不能回造；恢复后仅补读交易所可查询的成交与账单。

订单、撮合明细和完整开平仓周期分别展示。止损覆盖只说明挂单的方向、数量和平仓属性与持仓匹配，不保证实际成交价格。外部截图不计入实时覆盖。

本人复盘只有在确认平仓后新增或修改复盘文字、做对的地方或下一笔改进才计入；只修改标题或勾选标签不算完成。AI 报告按平仓后生成的报告单独统计，不能代替本人记录，也不能倒填原始开仓理由。

AI 只接收所选交易的相关记录、摘要和可选截图，不发送交易所密钥。支持 DeepSeek、OpenAI、Anthropic Claude、Google Gemini、OpenRouter，以及使用 OpenAI Chat Completions / Responses 或 Anthropic Messages 协议的自定义公网 HTTPS 接口；其他私有协议需另行适配。

在「连接设置 → AI 服务」选择服务商，填写模型 ID 和对应 API Key 后保存。可读取服务商模型列表，也可手填 ID。列表测试不调用模型，只验证列表接口，实际生成和图片能力需首次复盘验证。纯文本模型不会收到图片，报告会标记未读取截图。不同服务商的密钥独立保存，空值只保留同一服务商、同一地址的已有密钥；更换自定义地址需要重新填 Key。旧 DeepSeek 配置会兼容迁移。

策略实验与历史回测功能已停用，相关 API 返回 410，旧实验数据保留归档。开仓计划直接记录理由、失效条件和风险，仍需通过账户风险检查、AI 审核及本人确认；历史绑定实验的计划需重新保存和审核。单笔审核不能证明策略有效。本仓库测试使用隔离数据和模拟模型响应，不证明任何模型预测能力。

## 分享交易与复盘

「分享」可生成月报、年度至今报告或单笔交易卡片；日志也有「分享这笔交易」入口。按交易所和日期筛选，设置昵称和独立分享感想，再预览或导出 PNG。图片由浏览器使用与预览相同的画布生成，无外部截图服务。手机支持放大阅读、文字摘要和日期选择。

金额、价格及最近平仓明细默认隐藏。隐藏字段在服务端就被移出报告对象，不只是前端遮挡。贡献格子默认显示每笔日志的首次有效平仓后复盘活动，也可切换每日盈亏；隐藏金额时仅表示盈亏正负。本人笔记、AI 原文、订单 ID、账户 UID 和 API 密钥不会随报告发布。单笔模板会展示用户主动选择的交易对与方向；盈亏只显示已确认完整轮次的平仓盈亏，手续费分列，资金费仍未分配到单笔。

平仓统计按完整交易轮次去重，不将撮合数当作交易次数。复盘完成率以所选期间已确认完整平仓为分母，复盘天数按首次有效复盘日期计算，二者口径不同。覆盖日历区分未采集、部分覆盖、全天覆盖和未来日期；新版累积实际读取成功的账单区间；旧版覆盖标记需要重新同步验证，未证明完整的历史不会回造。Variational 手动记录不计入已对账收益。

只有点击「生成分享链接 → 确认发布此报告」才创建公开链接。链接包含固定的脱敏快照，可选择 7 / 30 / 90 天有效期，最多 200 条有效链接；可以随时撤销。公开页面和 API 使用 `no-store`，不读取私人账户 API，报告不会跟随之后的交易更新。公开页面每 30 秒或重新激活时重新验证链接；撤销阻止后续访问，已下载或截图的内容无法收回。未发布预览最多保留 24 小时、最近 100 份；清理在生成新预览时进行。

## OKX 与 Bybit 接入

在「连接设置」展开对应交易所，填写自己的只读凭证：

| 交易所 | 凭证 | 当前范围 |
| --- | --- | --- |
| OKX | API Key、Secret、创建 API 时设置的 Passphrase | 全球站、USDT 线性永续 |
| Bybit | API Key、Secret | 全球站、统一交易账户 UTA、系统生成的 HMAC Key、USDT 线性永续 |

每家交易所绑定一个账户，可轮换同一账户的密钥；不同账户会拒绝合并。支持单向和双向持仓，OKX 按 `ctVal × ctMult` 将张数换算为基础币。未接入地区独立站点、Bybit 经典账户/RSA 密钥、测试网、现货、交割合约、币本位和 USDC 合约。

验证并保存只证明账户身份读取成功，首轮同步才会验证成交、挂单和账单权限。默认约每 60 秒轮询，首轮补读近 30 天；设置中可暂停或手动补读近 7 / 30 / 90 天。每轮重读近 7 天以容纳延迟入账，分页完整且持仓核对通过才提交。网络错误、缺少合约元数据、Bybit 成交与账单/订单未对齐时保留上次快照，显示原因并退避重试。实际快照间隔取决于网络和分页量；离线历史仓位快照不会回造。

账户、成交和账单按交易所隔离；同名交易对或订单编号不会相互串账。开仓、加减仓和平仓会进入同一套自动日志及 AI 复盘；已有手写理由保持原样。首页账户权益只显示 USDT 币种权益，可能包含该账户其他产品，不能理解为“永续专用权益”。已实现净额只统计本次同步范围内的 USDT 永续账单；手续费和资金费各计一次，划转不算交易盈利。单笔周期资金费仍标记“未分摊”，不会伪装成已验证净收益。

本阶段自动保存成交、仓位和挂单变化；OKX / Bybit 已支持日志回放与开仓咨询的公开历史 K 线，但尚未接入持续行情采样与含费保本价。正式风险政策与纪律审核仍仅适用于 Binance，其他交易所可使用独立的开仓前咨询；不会把它们误归为已审核或违规。已下架且从未保存过元数据的合约、不能核对的成交顺序及非 USDT 结算费用需要人工核对，系统会明确显示同步未完成。

协议依据：[OKX V5 文档](https://www.okx.com/docs-v5/en/)、[Bybit 成交](https://bybit-exchange.github.io/docs/v5/order/execution)、[Bybit 账户账单](https://bybit-exchange.github.io/docs/v5/account/transaction-log)。测试使用合成响应；没有配置真实 API Key 前，不能声称完成真实账户联调。

## 多交易所合并账本

「收益分析」默认展示 Binance、OKX、Bybit 的合并账本，可勾选参与账户，选择近 7 / 30 / 90 天，也可切换单个账户。当前每家交易所支持一个账户；不同交易所可以同时连接，轮换密钥必须属于原账户。Variational 截图和手工记录暂不加入已核对收益。

合并只使用所选账户**共同覆盖的最近一段连续时段**，实际起止时间会显示在金额上方。某账户只采集了 7 天，就不会把另一账户 30 天的收益加进去。缺少完整账单时显示待核对，只有已验证的空时段才显示零。首次升级后需重新同步；旧覆盖标记不会自动成为新账本的有效凭据。

计算遵循以下口径：

- 已实现净额 = 平仓盈亏 + 有符号手续费净额 + 有符号资金费；返佣为正。原始账单是金额来源，成交明细不会重复贡献费用或盈亏。
- 充值、提现、账户划转和已识别的非交易奖励不计为交易盈利。不同币种分开显示，不假设 USD、USDT、USDC 等价。
- 后端使用 Decimal，金额通过字符串传输，前端按十进制字符串格式化；原始账单编号以字符串保存。按交易所、账单类型和编号去重，跨交易所相同编号互不覆盖。
- 每次核对账户合计、日期合计、交易对合计和费用分项；未知账单、冲突编号或无效金额会停止展示合计，并保留待核对项。分项一致不代表交易所不存在延迟入账，自动同步重读近 7 天以补入迟到记录。
- 浮动盈亏与已实现净额分开。单笔轮次仍未分摊资金费，不能把该轮次盈亏当成已验证的最终净收益。

Binance 使用官方只读账户信息中的 UID 绑定账本，避免替换密钥时混入其他账户；需要该账户信息接口的读取权限，应用不调用现货下单接口。身份无法验证时保留旧账本并停止同步。

账单符号依据：[Bybit transaction-log](https://bybit-exchange.github.io/docs/v5/account/transaction-log) 的 `change = cashFlow + funding - fee`、[OKX V5](https://www.okx.com/docs-v5/en/) 的有符号 `pnl` / `fee`；Binance 身份依据为 [Account information](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md#account-information-user_data)。测试覆盖重复账单、同号跨账户、返佣、未知类型、覆盖断档、账户换绑和超过 JavaScript 安全整数的金额；真实账户的权限与账单仍需首次同步核验。

## 部署

以单个常驻服务运行，置于 HTTPS 反向代理之后。公网部署必须通过 `auth.py` 配置登录，并设置 `--public-origin`；使用 `python3 auth.py --help` 和 `python3 server.py --help` 查看本版本参数。`data/`、附件和研究结果使用持久化目录，密钥单独管理。

例如，在 HTTPS 反向代理后的单用户实例中：

```sh
# 交互设置密码，至少 12 位；不会把密码写进命令历史。
python3 auth.py --username admin
python3 server.py --host 127.0.0.1 --port 8765 --public-origin https://journal.example.com
```

将你自己的 HTTPS 域名反向代理到 `127.0.0.1:8765`，由 systemd 或其他进程管理器保持服务常驻。应用适合个人单用户部署，目前不提供多租户隔离或多人账户管理。登录后修改设置前，确保浏览器访问的地址与 `--public-origin` 一致。

密码、API Key 与账本都存储在实例磁盘上，API Key 不做磁盘加密；需要依靠主机文件权限和加密备份保护它们。不要把运行目录、真实截图或密钥添加到 Git。备份和恢复由部署者负责。

更新前使用 SQLite backup API 创建一致快照并备份旧源码。只发布本次变更的源码，不覆盖线上数据库、认证文件或附件；保留回滚版本。具体主机、证书、账号与运维记录应保存在部署者的私密文档中。

## 验证

```sh
python3 -m unittest discover -s tests -v
node --test tests/*.cjs
node --check static/app.js
node --check static/training.js
```

浏览器验收使用隔离账本，验证保存后刷新、筛选、AI 未配置引导、复盘进度、手机布局。不要在生产账本中创建测试交易。

## 项目结构

- `server.py` / `auth.py`：HTTP 服务、登录会话与请求校验。
- `journal.py` / `recorder.py`：SQLite 账本、只读同步、成交周期与过程快照。
- `trade_context.py` / `stop_coverage.py`：行情、挂单与止损覆盖核对。
- `ai_provider.py` / `ai_review.py`：可选模型服务与证据复盘。
- `training.py` / `pretrade_*.py`：事前计划、账户风险规则和审核记录。
- `static/`：原生 JavaScript 界面、样式和通用图标。
- `tests/`：隔离数据库与合成测试数据，不访问真实账户。
- `backtest.py`：停用功能的历史兼容模块；无可用页面或 API 入口。
